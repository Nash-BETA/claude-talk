# claude-talk

マイクに「クロード、〜」と話しかけると [Claude Code](https://code.claude.com/) が答え、その返答を音声で読み上げる macOS 用の常駐プログラムです。
キー操作なしで、普段の Claude Code と声で会話できます。

```
マイク → 発話区間の検出 (webrtcvad) → ローカルで文字起こし (mlx-whisper)
  → 呼びかけ語の判定 → claude -p (stream-json で常駐) → say で読み上げ
```

## 特徴

- **キー操作が要らない**: 呼びかけ語（「クロード」）で始まる発話だけを拾います。Claude Code 標準の `/voice` は録音開始にキー操作が必要です
- **普段の Claude Code のまま**: CLAUDE.md・rules・Skill・MCP・メモリ・フック・権限ルール（allow / deny）を普段どおり読み込みます。権限モードだけは、設定に関係なく auto で起動します（`--permission-mode` で変更できます）
- **音声は外に出さない**: 文字起こしは Apple Silicon 上のローカルモデル（mlx-whisper）で行います。Claude に送るのは文字だけです
- **返事が速い**: `claude` を起動したままにして会話を続けるので、発話のたびに起動を待つことがありません
- **どのアプリを見ていても状態が分かる**: 待機中・聞き取り中・考え中などの状態をメニューバーに出します

## 必要なもの

- macOS（Apple Silicon）
- [uv](https://docs.astral.sh/uv/)
- [Claude Code](https://code.claude.com/) の CLI（claude.ai のアカウントでログイン済みであること）。2.1.314 で動作を確認しています
- マイク

## セットアップ

```bash
git clone https://github.com/Nash-BETA/claude-talk.git
cd claude-talk
uv sync
```

初回起動時に文字起こしモデル（約 1.6GB）を Hugging Face からダウンロードします（`~/.cache/huggingface/` に保存されます）。

## 使い方

```bash
uv run voice_claude.py --workdir ~/path/to/your/projects
```

`待機中` と表示されたら話しかけてください。終了は Ctrl+C です。
`--workdir` は、普段 Claude Code を起動しているディレクトリを指定します（省略すると起動したディレクトリになります）。プロジェクトの CLAUDE.md やメモリは、このディレクトリを基準に読み込まれます。

| 話しかけ方 | 動き |
| --- | --- |
| 「クロード、〜」 | 「〜」を Claude に送り、返答を読み上げる |
| 「クロード」だけ | 返事はせず、状態表示に「続けてどうぞ」を出して、8 秒以内に話し始めた発話を呼びかけなしで受け付ける |
| 返答のあと 8 秒以内に話し始めた発話 | 呼びかけなしで続きとして送る |
| 「クロード、新しい会話」 | 会話をリセットする |

受け付けると「チン」と鳴ります。返答の全文は画面に表示され、長い返答は冒頭だけを読み上げます。

呼びかけ語は読みで比べるので、「クロド」「グロード」「クロウド」のような聞き取りの揺れも呼びかけとして扱います。
「クラウド」「クロス」のような別の言葉や、「黒と白」「玄人」のように漢字を含むものは扱いません（読みが同じでも呼びかけではないことがほとんどのため）。
「あの、」「えっと」のような一言が前に入っても受け付けます。ただしその場合は、「クロード、」「クロードさん」のように呼びかけのあとに区切りが必要です。「さっきクロードに聞いたら」のような、会話の中で名前が出ただけの発話を拾わないためです。

今の状態は、メニューバーとターミナルの最下行に表示されます。ほかのアプリを見ているときは、メニューバーで確認できます。

メニューバーには短い表示が出ます。待機中・聞き取り中・続けてどうぞのときは、末尾の 1 文字（▁〜█）がマイクの音量です。話している間に伸び縮みしていれば、声を拾えています。

```
🎙 待機中 ▂
👂 聞き取り中 ▆
⠹ 文字起こし中
⠼ 考え中 3秒
🔊 読み上げ中
🎙 続けてどうぞ 6秒 ▁
```

ターミナルの最下行には、同じ状態を音量のバー付きで表示します。

```
🎙  待機中  ██··········
👂 聞き取り中  ███████·····  1.2 秒
⠹ 文字起こし中
⠼ 考え中  3 秒
🔊 読み上げ中
🎙  続けてどうぞ（あと 6 秒）  █···········
```

「続けてどうぞ（あと N 秒）」は、呼びかけなしで話し始められる残り時間です。
ターミナルの最下行はターミナルで実行したときだけ出ます（パイプやファイルへの出力では出ません）。`--wav` ではどちらも出ません。

メニューバーが混んでいると、項目がノッチ（画面上部の切り欠き）の裏に隠れて見えないことがあります。その場合は、ほかのアプリの項目を減らすか、⌘ を押しながらドラッグして並びを変えてください。claude-talk の項目も ⌘ を押しながらドラッグして動かせます。

## オプション

| オプション | 既定 | 内容 |
| --- | --- | --- |
| `--workdir` | 起動したディレクトリ | Claude Code を起動するディレクトリ |
| `--model` | Claude Code の設定どおり | Claude のモデル。返事の速さを優先するなら `sonnet` |
| `--permission-mode` | `auto` | 権限モード。承認が必要な操作は確認画面を出せないため自動で拒否されます。`bypassPermissions` は聞き間違いがそのまま無確認で実行されるので勧めません |
| `--tools` | 絞らない | 組み込みツールを絞る（例: `Read,Grep,Glob`）。**MCP のツールは対象外**です |
| `--timeout` | `600` | 最後の出力からこの秒数、何も返ってこなければ打ち切る |
| `--safe-mode` | なし | CLAUDE.md・フック・MCP・Skill を読み込まない。軽く速くなりますが、普段の Claude とは別物になります |
| `--wake` | クロード / claude | 呼びかけ語。複数指定できます。読みで比べるので表記の揺れも拾います |
| `--followup` | `8` | 返答後に、呼びかけなしで話し始められる秒数（0〜60）。`0` で無効。「クロード」だけのあとの受付は、この値に関係なく 8 秒です |
| `--end-silence` | `1.2` | この秒数黙ったら話し終わりとみなす（0.3〜5.0）。短くすると返事が早くなりますが、「クロード、」のあとの間で区切られやすくなります |
| `--voice` / `--rate` | `Kyoko` / 既定の速さ | 読み上げの声と速さ（`say -v '?'` で声の一覧が出ます） |
| `--readings` | `~/.config/claude-talk/readings.txt` | 読み替えの一覧のファイル（「読み間違いを直す」を参照）。無ければ使いません |
| `--device` | システムの既定 | マイク。`--list-devices` で一覧を表示します |
| `--vad-level` | `2` | 発話検出の厳しさ（0〜3、大きいほど厳しい） |
| `--debug` | なし | 入力レベル・発話の検出・無視した発話を表示します |
| `--wav` | なし | マイクの代わりに WAV ファイルを流します（動作確認用） |
| `--no-speak` | なし | 読み上げずに画面表示だけにします |
| `--no-menubar` | なし | メニューバーに状態を出しません |

## 読み間違いを直す

macOS の読み上げ（`say`）は、漢字の読みを間違えることがあります（例: 「月初」を「つきはつ」）。
読み間違える語は、読み替えの一覧に書いておくと、読み上げる直前にひらがなへ置き換えます。画面に出す文は漢字のままです。

一覧は `~/.config/claude-talk/readings.txt` に、UTF-8 で 1 行に「語 読み」を空白で区切って書きます。語にも読みにも空白は入れられません。`#` から後ろはコメントです。

```
# 社内でよく使う言葉
工数 こうすう
上期 かみき
```

- 「月初（げっしょ）」と「期初（きしょ）」は、書かなくても置き換えます。ただし「11月初旬」「今月初め」「学期初め」のように別の語の一部になっているときは、置き換えずにそのまま読ませます
- 一覧に書いた語は、文の中のどこにあっても置き換えます。たとえば「工数」を登録すると、「作業工数」の中の「工数」も置き換わります
- 置き換えは文の頭から順に行い、同じ位置から始まる語は長い方が優先されます。別の語の中で置き換わって困るときは、その語を同じ位置から始まる形で登録してください。読みに同じ文字を書くと、その語は置き換えずにそのまま読ませられます（例: 「工数表 工数表」）
- 既定の「月初」「期初」も、一覧に書けば読みを変えられます。「月初 月初」と書けば置き換えなくなります
- 英字の語（「PR」など）は、英単語の途中（「PRODUCTION」の「PR」など）では置き換えません
- 一覧は起動時に読み込みます。書き足したら claude-talk を起動し直してください

声そのものを良くしたい場合は、高品質版の声を入れてください。標準で入っている Kyoko は、音声データの小さい簡易版（compact）です。高品質版の方が読みの精度も高い見込みですが、「月初」などが直るかは確かめていません。

1. システム設定 → アクセシビリティ → 読み上げコンテンツ → 「システムの声」の横の（i）→ 日本語から、Kyoko の高品質版（拡張・プレミアム）をダウンロードします
2. `say -v '?' | grep ja_JP` で、入った声の名前を確かめます
3. その名前を `--voice` に指定して起動します。名前に空白や括弧が入るときは、`--voice '名前'` のように引用符で囲みます

## プライバシーと安全性

- マイクは起動中ずっと音を拾います。拾った音はローカルで文字起こしし、呼びかけ語で始まらない発話は捨てます（`--debug` のときだけ画面に表示します）
- Claude に送るのは、呼びかけ語で始まる発話と、返答直後の受付時間中の発話の文字だけです。送った内容は Claude Code の通常の利用と同じ扱いになり、プランの使用量を消費します
- 既定の auto モードでは、ファイルの編集やコマンド、MCP 経由の操作（メッセージ送信など）も、判定器が通せば実行されます。**聞き間違いのまま実行される可能性があります。** そのため、取り消しにくい操作や外部に出る操作の前は、内容を読み上げてユーザーの「はい」を待つよう Claude に指示しています。ただしモデルへの指示なので、必ず守られる保証はありません
- **マイクに入った他人の声やスピーカーの音（会議・動画など）でも、呼びかけ語で始まれば Claude に送られ、あなたの権限で実行されえます。** 返答後の受付時間は呼びかけ語なしで受け付けるので、確認の「はい」も他人の声で通りえます。会議中や動画の再生中は止めてください
- 読み取り専用にしたい場合は `--safe-mode --tools Read,Grep,Glob` を付けてください。`--tools` が絞るのは組み込みツールだけで、MCP のツールは残ります（`--safe-mode` を付けると MCP ごと読み込まなくなります）。また `--permission-mode manual` でも、settings.json の `permissions.allow` にある操作は承認なしで実行されます
- 読み上げ中・考え中に拾った音は捨てます。自分の読み上げ音声を拾って会話がループするのを防ぐためです

## フックとの連携

音声セッションで起動する `claude` には、環境変数 `CLAUDE_TALK=1` が付きます。

`UserPromptSubmit` フックで短いプロンプトを止めている場合、話し言葉の発話はほぼ止められてしまいます。フック側で `CLAUDE_TALK` を見て素通しさせてください。
素通しさせるのは短文や曖昧な依頼のチェックだけにし、秘密情報の検出などの安全のためのフックには入れないでください。
なお環境変数は子プロセスに引き継がれるため、音声セッションの中から起動された `claude` にも `CLAUDE_TALK=1` が付きます。

```python
import os, sys

if os.environ.get("CLAUDE_TALK") == "1":
    sys.exit(0)
```

フックに止められたときは、ブロック文を読み上げず「フックに止められました」とだけ伝えます（全文は画面に出ます）。

## 設計メモ

- **`claude -p` を stream-json で常駐させる**: 発話のたびに `claude -p` を起動すると 1 往復 5〜8 秒かかりました。`--input-format stream-json` で起動したままにすると、2 回目以降は約 1 秒です（`--safe-mode`・sonnet での実測）
- **フックのブロックは成功扱いで返ってくる**: `UserPromptSubmit` フックがプロンプトをブロックすると、`-p` ではそのブロック文が `is_error: false` の正常な返答として返ります。文面で判定して、読み上げを差し替えています
- **Stop hook による読み上げは使わない**: `-p` 実行でもフックは動くため、全体設定に読み上げフックを入れると、スクリプトから実行している他の `claude -p` まで喋り出します
- **Agent SDK は使わない**: ドキュメントが API キー認証を前提にしており、claude.ai ログインのまま使える `claude -p` を選びました
- **メニューバーの表示は別プロセス**: メニューバーの項目は、メインスレッドで AppKit のイベントループを回さないと出せません。メインスレッドはマイクの処理に使っているので、表示だけを補助プロセス（`menubar.py`）に任せ、表示する文字列を標準入力で送っています。本体が落ちて標準入力が閉じると、補助プロセスも終了します

## 制限事項

- ターミナルで使っている Claude Code の対話セッションとは、文脈を共有しない別セッションです
- 確認画面を出せないため、承認が必要な操作は自動で拒否されます
- 英単語やファイル名は聞き取りを誤りやすいです（例: `pyproject.toml` → 「PyProjectTomul」）。正確に伝えたい名前は画面で入力する方が確実です
- 読み上げは漢字の読みを間違えることがあります。読み替えの一覧で直せるのは、登録した語だけです
- 読み上げ中は割り込めません。止めたいときは Ctrl+C で終了してください
- 呼びかけ語は読みで比べるので、読みが同じカタカナ・ひらがなの言葉（「くろうと」など）で始まる発話にも反応します。逆に、呼びかけが漢字で聞き取られた場合は反応しません

## うまく動かないとき

まず `--debug` を付けて起動し、表示を確認してください。

| 表示の様子 | 原因 | 対処 |
| --- | --- | --- |
| 話しても音量のバー（メニューバーでは末尾の 1 文字）が動かない、`入力レベル` が -40 dBFS あたりより上がらない | 声がマイクに届いていない | マイク本体のミュートやゲインを確認します。-90 dBFS 前後に張り付くなら、起動したターミナルアプリにマイクの使用許可がありません（システム設定 → プライバシーとセキュリティ → マイク） |
| レベルは上がるのに `発話を検出` が出ない | 発話の検出が厳しすぎる | `--vad-level 0` で試します |
| `無視（呼びかけなし）: ……` が出る | 呼びかけ語が別の表記で聞き取られている | 表示された表記を `--wake` で追加します |
| 「フックに止められました」と言われる | `UserPromptSubmit` フックが発話を止めている | 「フックとの連携」のとおり、フック側で `CLAUDE_TALK` を見て素通しさせます |

## マイクなしで動作を確認する

`say` で作った音声を WAV にして流すと、マイクを使わずに一連の流れを確認できます。

```bash
say -v Kyoko -o test.aiff "クロード、pyproject.toml に書いてある依存ライブラリを教えて"
afconvert -f WAVE -d LEI16@16000 -c 1 test.aiff test.wav
uv run voice_claude.py --wav test.wav --no-speak --debug
```

## 開発

マイク・Claude・音声合成・メニューバーの実物に依存しない部分（呼びかけの判定、読み上げの整形、状態表示、受付時間の判定、メニューバーへの送信）はテストがあります。

```bash
uv run pytest
```
